# 완료 보류 복구 — 2026-09-20

게임 구현 실패가 아니라 완료 훅의 호스트 증거 판독 누락이었다. 기존 B2 게임 변경은 전용 브랜치에 이미 검증·push돼 있고 로컬 서버에 적용돼 있다.

## 확인한 원인

- `text((await tools.exec_command(...)).output)` 및 결과를 괄호로 감싼 호출을 기존 리터럴 파서가 인식하지 못했다.
- 혼합 배치의 실패가 같은 cell의 `wait` 응답으로 돌아오는 경우도 이 문법에서는 연결되지 않았다.
- 먼저 시작한 비동기 작업의 실제 종료 기록이 승인 시간 초과 뒤에 수집될 수 있다. 이때 실제 종료 증거까지 확인해야 한다.
- 호스트의 Reasoning 완료 이벤트는 프로세스 실행이 아니다. 미확인 추가 실행 판정에서 CommandExecution/FileChange와 구분해야 한다.

실제 두 사례는 같은 세션/턴/바깥 호출의 원문·준비 시각·실패 반환과 선행 프로세스의 native 종료 이벤트를 대조했다. 패치 실패는 failed, 승인 시간 초과는 not_started, exit_code는 null로 보존한다. 원래 실패를 성공으로 바꾸지 않는다.

## 수정 범위와 검증

`tools/task-finish/recovery.py`는 설치된 `gate.py`에 판독기와 새 Pre 입력 연결만 추가한다. 기존 코드 앵커·설치 전 SHA-256을 확인하고 변경된 설치본에는 적용을 거부한다. 백업을 만든 뒤 원자적으로 적용하며 hooks.json/config.toml/AGENTS.md/SESSION_MEMORY.md의 해시는 보존한다. 원본 로그·실제 상태 DB·Git 소유권·Stop 완료 검사·인증·훅 신뢰 설정은 편집하지 않는다. 종료 증거의 실제 반영은 설치 후 공식 `gate.py reconcile`이 수행한다.

새 판독기는 동적 JavaScript를 실행하지 않는다. 순차 literal 호출과 빈 poll만 허용한다. stdout만 표시한 선행 단계는 native 출력까지 일치해야 한다. 실행 중 응답 자체는 종료가 아니며 모든 시작된 선행 작업에 실제 terminal 이벤트가 있어야 한다. 새 버전은 Pre에서 정확히 연결된 입력만 복구하고, 기존 버전에서는 당시 지원되지 않았던 새 문법에 한해서만 같은 증거 검사를 적용한다.

- 새 회귀 시험: 15개 통과. 누락/중복/잘못된 턴, 실행 중·실패를 출력한 셸, 추가 실행/파일 변경, 다른 cell·취소·중복 wait, 잘못된 process ID, 기존 입력 불일치, 동적 문법은 거절한다.
- 실제 두 호스트 기록의 읽기 전용 판정에서 각각 failed/not_started와 선행 종료 ID 및 증거 SHA-256을 확인했다.
- 기존 전체 완료 훅 회귀 시험: 격리 후보에서 157개 통과(204초). 이후 추가한 FileChange 경계와 테스트 재현성 보완은 새 시험 15개로 확인했다.

설치 및 공식 reconcile 결과 확인 전이다. 실제 검증 후 이 절을 갱신한다.
