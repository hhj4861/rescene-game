## 1. 한 줄 컨셉

> 리센느 다섯 멤버 중 한 명이 되어, 연습생 시절부터 2026년 첫 1위까지의 실제 서사를
> 메이플스토리 스타일 2D 횡스크롤 액션 RPG로 다시 걷는 **팬메이드 비영리 브라우저 게임**.

| 항목 | 결정 |
|---|---|
| 장르 | 2D 횡스크롤 액션 RPG (플랫포머 + 퀘스트 + 성장) |
| 플랫폼 | 웹 브라우저 (데스크톱 키보드 우선, 모바일은 후순위) |
| 플레이 형태 | 싱글플레이 (멀티는 범위 밖, 단 시스템은 서버 이식 가능하게 결정론적으로 설계) |
| 엔진 | Phaser 3 (현재 프로토타입 유지) + TypeScript + Vite |
| 플레이 시간 목표 | 장면 7개(프롤로그 0 + 본편 1~6), 총 3~4시간 (수직 슬라이스는 20~30분) |
| 성격 | 팬메이드 · 비영리 · 실명/사진/음원 미사용, 도트 치비 스타일라이즈 |

### 이름 유래

- 그룹명 RESCENE = RE + SCENE + SCENT(향기로 장면을 다시 떠올린다) → 게임의 챕터를 **"장면(Scene)"**, 저장 지점을 **"향기(Scent)"**라 부른다.
- 팬덤명 REMINE(리마인, RESCENE+MINE) → 게임 내 팬 NPC 종족명. 애칭 "레미니".

## 2. 설계 원칙

1. **데이터 주도 콘텐츠.** 챕터·맵·퀘스트·대사·스킬·유행어는 전부 JSON/TS 데이터. 리센느가 다음 컴백을 하면 코드 수정 없이 **챕터 7을 추가**할 수 있어야 한다.
2. **엔진 독립 시스템.** 전투 계산·성장·퀘스트·대화·저장 로직은 Phaser를 import하지 않는 순수 TS 모듈로 두고 Vitest로 검증한다. Phaser 씬은 얇은 표현 계층이다.
3. **수직 슬라이스 우선.** 챕터 0~1을 끝까지(이동→전투→퀘스트→보스→저장) 먼저 완성한 뒤 챕터를 늘린다.
4. **사실 기반 서사, 추상화된 적.** 실제 연표·유행어를 그대로 쓰되, 적은 "악플 까마귀", "무관심 안개"처럼 **의인화된 감정/장애물**만 쓴다. 실존 타 그룹·개인을 적으로 만들지 않는다.
5. **멤버 외 실존 인물은 역할 NPC로.** 사장님, 매니저, 안무 선생님, 심사위원, MC, 연수 아저씨처럼 역할명으로만 등장한다. 비공인 개인(가족 등)의 실명은 쓰지 않는다.

### 스탯

| 스탯 | 게임 내 이름 | 의미 |
|---|---|---|
| HP | 체력 | 0이면 "무대 실수" → 마지막 향기(저장 지점)로 |
| MP | 기력 | 스킬 자원 |
| ATK | 끼 | 물리/음파 데미지 |
| DEF | 멘탈 | 피해 감소 |
| SPD | 스피드 | 이동/공속 |
| LUK | 기회 | 크리티컬 확률 |

## 5. 유행어(밈) 시스템 — "리센느 사전"

메이플의 링크 스킬/칭호에 해당하는 리센느만의 핵심 시스템이다.

- **획득**: 퀘스트 보상, 특정 NPC 대화, 챕터 클리어, 숨겨진 오브젝트 조사.
- **도감(Codex)**: 카드 형태. 앞면은 문장, 뒷면은 출처(누가·어디서·언제)와 짧은 해설. 팬 입문 가이드 역할.
- **장착**: 유행어 슬롯 3개(챕터 1에서 1개, 이후 확장)에 장착하면 **패시브 효과**.
- **이모트**: 장착한 유행어를 키로 출력 → 말풍선 + 효과음(합성음, 실제 음성 아님). 일부 NPC는 특정 유행어에 반응(숨은 퀘스트 트리거).
- **인지도(Fame) 연동**: 유행어를 NPC 앞에서 쓰면 인지도 소량 획득. 챕터 5에서 "거제, 야호~!"를 각 고향 맵에서 쓰면 홍보대사 퀘스트 진행.

## 6. 게임 시스템

### 6.1 이동 (메이플 문법)

- 좌우 이동, 점프, **2단 점프**(레벨 10 해금), 아래+점프로 원웨이 플랫폼 내려가기
- 사다리/로프(위/아래 키), 포탈(위 키)
- 벽·천장 없는 넓은 맵, 카메라는 플레이어 추적 + 맵 경계 클램프
- 물리: Phaser Arcade (현재 설정 유지, 중력 800)

### 6.2 전투

- 기본 공격(근접/원거리는 클래스별), 스킬 4개 퀵슬롯 + 궁극기
- 히트박스/허트박스 분리, 피격 무적 0.6초, 넉백
- 데미지 = `max(1, (끼 × 스킬배율 − 멘탈 × 0.5)) × 크리(1.5) × 랜덤(0.9~1.1)`
- 적 AI: `patrol` / `chase` / `ranged` / `boss(페이즈 스크립트)` 4종. 데이터로 타입·스탯·드롭 정의
- 데미지 숫자 팝업, 피격 플래시

### 6.3 성장·아이템

- 경험치 → 레벨, SP로 스킬 강화(각 스킬 최대 10)
- 통화 **하트**(lip bomb 타이틀 Heart Drop에서) — 적 드롭, 퀘스트 보상, 상점
- 수집품 **포카**(포토카드) — 희귀 드롭, 도감 100% 시 칭호
- 소모품: 멤버 최애 음식 (원이 물회 · 리브 엽떡 · 미나미 설렁탕 · 메이 떡국 · 제나 마라탕) — 회복량/부가 효과 차등
- 장비 슬롯 4개: 인이어(멘탈) · 무대의상(체력) · 마이크(끼) · 운동화(스피드)
- 인벤토리: 탭 4개(장비/소모/기타/포카), 격자 24칸에서 시작

### 6.4 퀘스트

- 상태 `available → active → completable → done`
- 목표 타입: `kill(적, n)` · `collect(아이템, n)` · `talk(npc)` · `reach(map)` · `minigame(id, 점수)` · `emote(유행어, map)`
- 보상: 경험치 · 하트 · 아이템 · 유행어 카드 · 인지도 · 플래그
- 선행 조건: 레벨, 챕터, 플래그, 클래스(멤버 전용 퀘스트)
- 퀘스트 로그 UI(메인/서브 탭), 맵 위 NPC 머리 느낌표/물음표

### 6.5 대화

- JSON 스크립트: 노드 배열, 각 노드 = 화자 · 초상화 표정 · 텍스트 · 선택지 · 조건 · 플래그 설정
- 타자기 효과, 스킵, 초상화 좌우 배치, 이름표
- 멤버별 말투 태그(경상도 사투리 원이/제나, 조곤조곤 메이, 존댓말 미나미 등)는 대사 텍스트 자체로 표현

### 6.6 인지도 (Fame)

- 0~100 게이지, 챕터 진행 게이트 겸 상점 해금 조건
- 획득: 퀘스트, 유행어 이모트, 미니게임 점수, 챌린지 촬영
- 챕터 4는 낮은 인지도(무명기)를 구조적으로 체험하고, 챕터 5에서 폭발하도록 곡선을 설계

### 6.7 미니게임 (3종, 챕터 순서대로 해금)

| 미니게임 | 챕터 | 형식 |
|---|---|---|
| 리듬 무대 | 2 | 4키 노트 타이밍. 음악은 **오리지널 칩튠**(실제 음원 미사용). 보스전 페이즈로도 사용 |
| 러닝 3.26km | 3 | 오토러너, 장애물 점프, 거리 게이지 3.26km |
| 챌린지 촬영 | 5 | 포즈 QTE(갸루피스 등) 타이밍 판정, 점수 → 인지도 |

### 6.8 저장

- localStorage, 슬롯 3개, 스키마 버전 필드 + 마이그레이션 함수
- 저장 지점 = **향기(Scent) 오브젝트** (허브·각 맵 입구·보스 앞). 수동 저장 + 챕터 클리어 자동 저장
- 저장 데이터: 멤버, 레벨/스탯/SP, 스킬 레벨, 인벤토리, 장비, 하트, 포카, 유행어(획득/장착), 퀘스트 상태, 플래그, 인지도, 현재 맵/좌표, 플레이 시간

### 6.9 UI (메이플 오마주)

- 하단 바: 체력/기력 바, 레벨·경험치 바, 퀵슬롯 8칸, 메뉴 버튼
- 좌상단 미니맵, 우상단 챕터/퀘스트 트래커
- 메뉴 창(I 인벤토리 · K 스킬 · Q 퀘스트 · C 리센느 사전 · E 장비), 창은 드래그 가능
- 폰트: 픽셀 한글 폰트(예: Galmuri, OFL) — 라이선스 확인 필수

### 8.3 씬 흐름

```
Boot → Preload → Title → CharacterSelect → World(mapId)
                                              ├─ Hud (parallel)
                                              ├─ Dialogue (overlay, World pause)
                                              ├─ Menu (overlay)
                                              ├─ Cutscene (챕터 인트로/아웃트로)
                                              └─ Minigame (World sleep → 결과 → World wake)
```

- `WorldScene`은 맵 ID를 받아 Tiled JSON을 읽고 레이어를 해석한다: `ground`(충돌) · `platforms`(원웨이) · `ladders` · `portals` · `spawns_enemy` · `spawns_npc` · `savepoints` · `decor`
- 맵 이동 = `WorldScene.restart({ mapId, spawnId })`. 상태는 `GameState`에 있으므로 씬 재시작에 안전

### 8.4 시스템 인터페이스 (순수 TS)

```ts
// systems/combat.ts
export function calculateDamage(
  attacker: Stats, defender: Stats, skill: SkillDef, rng: () => number,
): { amount: number; crit: boolean };

// systems/progression.ts
export function xpForLevel(level: number): number;
export function applyXp(state: PlayerState, xp: number): { state: PlayerState; levelsGained: number };

// systems/quest.ts
export class QuestEngine {
  constructor(defs: QuestDef[], state: QuestState, flags: FlagStore);
  available(): QuestDef[];
  start(id: string): void;
  report(event: GameEvent): string[];       // 완료 가능해진 퀘스트 id 반환
  complete(id: string): Reward;
}

// systems/dialogue.ts
export class DialogueRunner {
  constructor(script: DialogueScript, flags: FlagStore);
  current(): DialogueNode;
  next(): boolean;                          // false면 종료
  choose(index: number): void;
}

// systems/save.ts
export function serialize(state: GameStateSnapshot): string;
export function deserialize(json: string): GameStateSnapshot;   // 버전 마이그레이션 포함
```

`GameEvent`는 `enemy_killed | item_collected | npc_talked | map_entered | minigame_scored | emote_used` 유니온이다. 씬은 이벤트를 `EventBus`로 흘리고, `QuestEngine.report`가 소비한다.

### 8.6 프레임 루프 책임 분리

1. 입력 → `Player`가 의도(이동/점프/스킬 id)로 변환
2. `skills.ts`가 자원·쿨다운 확인 후 효과 명세 반환 → `WorldScene`이 히트박스 생성
3. 충돌 → `combat.calculateDamage` → `Enemy.takeHit` → 사망 시 `EventBus.emit('enemy_killed')` + 드롭
4. `QuestEngine.report` → HUD 트래커 갱신
5. 저장 지점 상호작용 → `save.serialize(GameState.snapshot())` → localStorage

## 10. 테스트 전략

| 계층 | 도구 | 대상 |
|---|---|---|
| 단위 | Vitest | 데미지 공식 경계값, 경험치 곡선 단조성, 퀘스트 상태 전이, 대화 분기/플래그, 저장 직렬화 왕복, 유행어 패시브 합산 |
| 데이터 | Vitest | 모든 JSON이 zod 통과, id 참조 무결성, 챕터별 메인 퀘스트 체인이 끊기지 않음 |
| 스모크 | Playwright | 부트 → 타이틀 → 캐릭터 선택 → 첫 맵 진입에 콘솔 에러 0 |
| 플레이테스트 | 체크리스트 | 챕터별 20분 플레이, 막힘/밸런스 기록 |

## 13. 열린 결정 — 사용자 확인 필요

이 문서는 아래 가정으로 작성했다. 다르면 알려주면 해당 섹션을 고친다.

1. **플레이어 = 멤버 5인 중 선택.** 대안: 플레이어가 "6번째 연습생" 또는 레미니(팬) 아바타로 멤버들과 동행. 추천은 멤버 선택(최애로 플레이, 메이플 직업 구조와 자연 매핑).
2. **싱글플레이.** 멀티(메이플처럼 다른 유저와 같은 맵)는 서버·계정·동기화가 필요해 범위 밖. 시스템은 결정론적으로 만들어 두어 나중에 얹을 수 있다.
3. **Phaser 유지 + TypeScript + Vite.** 대안: Godot(웹 export) 또는 PixiJS 직접 구현. Phaser는 이미 프로토타입이 있고 타일맵·물리 내장이라 유지 추천.
4. **아트는 도트 치비, 플레이스홀더 선행.** 직접 그리기/외주/AI 생성 중 무엇을 쓸지는 M8 전에 결정.
5. **톤은 유쾌·훈훈.** 악플·무명기 같은 어두운 요소는 추상화된 적으로만 다룬다.
6. **유행어 표기와 사건 날짜**는 나무위키·기사 기준. "거제, 야호~!" 원본 영상 시점은 출처가 3월/5월로 갈려 "2026년 봄"으로 표기했다. 팬 검수 필요.
7. **게임 제목** 가칭 "리센느스토리". 대안: "Re:Scene Online", "향기의 장면들".
