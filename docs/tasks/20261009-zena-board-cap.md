# 제나 게임판 크기 제한

- 목표: 작은 화면에서 판 전체를 읽고 조작할 수 있도록 무제한 확장을 없앤다.
- 범위/담당: 현재 Codex 단독, `fix/zena-board-cap-20261009` worktree. 기준 main `fd49675`.
- 규칙: 1–5단계 6×6 → 6–10단계 7×7 → 11단계 이후 최대 8×8. 스테이지 진행 자체는 계속한다.
- UI: 제나 판은 화면 높이에 따른 200px 축소 대신 캐비닛 폭을 사용한다. 작은 화면의 터치 칸 크기·전체 판 가시성·수평 넘침을 실제 브라우저에서 확인한다.
- 저장: 이전 무제한 크기도 검증 후 새 크기로 이관. 점수·목숨·시간·아이템·노래와 획득한 십원빵을 새 목표 범위에서 유지한다. 새 판의 실제 숨은 빵 수와 목표 문구를 일치시킨다.
- 완료 기준: 경계 단계·고단계·기존 저장 복원·십원빵 획득·모바일 입력 검증, 본인 변경 커밋/upstream push/PR. 새 PR 머지·운영 배포는 별도 승인 후 진행한다.
- 제나 결과: 전체 단위 186개, 린트·빌드, 관련 Chromium/모바일 Chromium/WebKit 브라우저 81개 통과. 320×568 화면에서도 최대 판의 칸은 28px 이상이며 판 내부와 페이지의 가로 넘침이 없다. 기존 큰 저장과 십원빵 원본 음성도 검증했다.
- 추가 사용자 요청: 모바일 영상은 게임 우선 접힌 재생 바/펼치기로 개선(사용자 선택 확인), 원이 게임에 네 멤버의 서로 다른 방해 이벤트를 추가. 같은 격리 브랜치에서 이어서 구현한다.

- 초기 검증: 의존성 오프라인 캐시에 rollup tarball이 없어 정상 npm ci로 설치했다. 첫 단위 검사는 185/186 통과했고, 제나의 숨은 영역 목표로 바뀐 규칙에 맞지 않는 종전 공통 개수 증가 검사를 갱신했다. 린트·빌드는 통과했다.

## 모바일 영상 디자인

- 기존 오락실 팔레트 유지: 잉크 #234454, 민트 #92bfb3, 종이 #fff9e9, 노랑 #f5d77e, 화면 배경 #edf4ef. Jua는 게임 제목, Noto Sans KR은 조작·상태 안내.
- 모바일: `[곡 이름 / 영상 펼치기] → [크게 확보한 게임판 + 조작] → [상세 안내]`. 44px 이상 토글, 펼치면 동일 플레이어가 나타나고 접어도 재생 위치를 재설정하지 않는다. 데스크톱 좌영상·우게임 배치는 유지.
- 검토: 새 장식이나 별도 카드 체계를 추가하지 않고 기존 게임 캐비닛에 맞춘 작은 제어 바만 추가한다. 결과 화면과 곡 고르기 미리보기는 기존 영상 크기를 유지한다.

- 미나미 원본: 사용자 Shorts hDi_kshHmFY(14초) 확보. 자막 429로 자막 요청은 중단했다. small 전사가 4분간 결과 없이 CPU를 사용해 본인 프로세스만 종료하고, 캐시된 base 모델·4스레드로 정확한 구간 확인을 재시도한다.

## 추가 기능 검증

- 모바일 영상: 선택한 접힌 재생 바를 리브·미나미 공식 영상 게임에 적용했다. 펼칠 때 동일 플레이어를 유지하고 데스크톱으로 넓히면 좌영상·우게임 배치로 돌아간다. 320px 화면의 큰 게임판/조작, 음소거·일시정지·재시도·결과 화면 연속 재생을 검증했다. 외부 YouTube 동작 검사는 API 대역을 포함한다.
- 원이: 매 단계 10/25/40/55초에 네 멤버가 순환 등장한다. 1.5초 예고 후 4초 효과. 리브는 중앙의 반투명 하트, 메이는 이동 속도 감소, 미나미는 좌우/길 터치 반전, 제나는 점프·공격 가능한 빵을 놓는다. 효과와 등장 횟수는 저장·복원하며 과거 저장은 지난 방문을 재실행하지 않는다.
- 기존 전체 단위 190개·린트·빌드, 관련 세 브라우저 99개 통과. 제나 빵 ID가 짝 몬스터와 충돌할 수 있어 단독 ID 발급으로 보완하고 회귀 검사를 추가했다.
- 모바일 WebKit의 실제 캡처에서 제나 8×8, 접힌 리브 영상 바와 큰 게임판, 미나미 방해 예고/효과 표시를 시각 확인했다. 산출물은 iCloud `rescene-game/zena-board-cap-20261009/`에 저장한다.
- 미나미 클리어 음성 교체는 같은 요청 범위로 이어서 진행 중이다.
