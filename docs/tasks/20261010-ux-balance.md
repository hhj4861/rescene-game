## 구현 및 검증 결과

- 모바일: 영상 위치와 iframe을 유지하는 접기/펼치기. 320×568과 390×844에서 게임판·필수 조작 표시. PC는 기존 좌측 영상.
- 게임 안내: 게임·노래 시계를 함께 정지하고 닫으면 이어간다. 탭 이탈 등 별도 정지가 발생하면 임의 재개하지 않는다.
- 원이: 가까운 간식만 유인하고 새 게임은 세 길 수집 도장을 요구한다. 이전 저장은 이미 달성한 것으로 복원한다.
- 제나: 2×3/3×2 매치 묶음을 우선 생성한다. 빈칸은 그대로 유지한다. 5단계마다 큰 빵, 다른 후반 단계는 작은 빵 여러 개. 이전 저장의 숨은 빵 위치는 breadLayout=1로 유지한다.
- 메이: 시작 성장치와 초반 12초 등장 완화, 체력·속도·등장 간격 곡선 조정.

### 같은 정책으로 비교한 결과

| 조건 | 이전 | 개선 |
|---|---|---|
| 원이 첫 곡 이후 무조작, 1–5단계 각 20시드 | 각 20/20 클리어 | 각 0/20 클리어 |
| 원이 적극 조작, 10개 단계 각 20시드 | 모두 20/20 | 모두 20/20 |
| 메이 회피·경험치 수집, 10/20단계 | 각 0/20 | 각 20/20 |
| 제나 밀대가 제거한 칸 비중, 10개 단계 | 66.4–72.8% | 37.1–50.3% |

자동 입력은 사람의 난이도나 승률이 아니다. 메이는 20단계의 단순 경로 순환 정책에서는 10/20, 무조작에서는 0/20이므로 회피·수집이 여전히 필요하다.

- 린트와 빌드 통과. 단위 테스트 207/207 통과.
- 1차 UI 검증: 신규 화면/정지 검사 통과. 기존 검사에서 리브 안내 재개 시 iframe 재생성 3건이 드러나 같은 플레이어를 재사용하도록 수정했다.
- 전체 브라우저 실행은 502 통과·18 실패·5 조건부 제외였다. 새 빵 배치/길 도장·접힌 영상에 맞게 fixture를 갱신한 5개 파일은 177/177 재검증 통과했다.
- 곡 선택 미리보기까지 접힌 회귀를 발견해 접기 CSS를 게임 화면에 한정했다. 최종 빌드의 펌프 미리보기·모바일 영상·UX 관련 검사는 51/51 통과했다. 자동재생 차단 시 영상이 펼쳐지고 게임 시계가 멈춘 채 재시도 가능한 동작을 포함한다.
- 전체 실행과 후속 검사를 테스트명/브라우저별로 합치면 523 통과·5 조건부 제외·미해결 실패 0이다. 제외 5건은 기존 CDP 터치 주입 및 터치 전용 조건이다. 단일 전체 실행이 전부 통과했다고 해석하지 않는다.
