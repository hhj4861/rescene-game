## 사용자 추가 요구와 검증 중 발견

- 제나: 최대 20×20. 퍼즐 아래 2×2·3×3·3×2, 8×8 등 영역의 모든 칸을 제거해야 신라빵을 얻으며, 모든 숨은 빵을 찾아야 클리어. 기존 점수만으로 종료하지 않는다. 더 큰 목표에 맞춰 기본 180초·36~80교환을 제공한다. 노래 획득 시 최소 60초 보장은 유지한다.
- 1차 E2E에서 9×9 판에 8×8과 2×2를 함께 배치할 수 없어 4단계 빵이 하나만 생성됨을 확인했다. 해당 단계 큰 영역을 7×7로 조정하고, 후기 단계 작은 빵은 판 전체에 분산해 위쪽 몇 줄만 반복 제거하는 공략을 방지한다.
- 확대 캡처에서 저해상도 번짐을 확인해 제나 캔버스를 기본 2배·확대 3배로 렌더한다. 확대 시 터치는 스크롤과 두 번 탭, 마우스는 드래그를 지원한다.
- 기존 결과 노래 E2E는 제나의 옛 점수 클리어와 3.5초 음원을 전제로 해 새 조건에 맞춰 fixture와 길이 단언을 갱신한다. 실제 게임 결함과 테스트 전제 변경을 구분한다.
- 음원: 메이/제나 공식 원본 10~70초, 그룹 다섯 곡 공식 MV 20~80초. ffprobe로 각 파일 60.000초, 원이 기존 파일 41.000초 확인. 짧은 구간 반복을 사용하지 않는다. 첫 다운로드는 구형 yt-dlp 403 실패, 작업별 캐시의 2026.08.19 버전과 Node 런타임으로 재시도 성공. 전역 도구 설치는 바꾸지 않았다.

- WebKit은 MP3 패딩을 포함해 길이를 60.029387초로 보고한다(Chromium/ffprobe 60.000초). 비반복·실제 재생 통과를 유지하고 길이 검증에 0.05초 허용 오차를 적용한다.

- 최종 빌드 검증 중 결과 노래 테스트 helper가 board만 전달하는 호출에서 breadCover를 읽는 오류를 발견했다. 게임 소스와 빌드는 변경 없이 fixture의 명시적 clear 플래그로 분기하도록 수정하고 해당 시나리오를 세 브라우저에서 재검증한다.

- 호환성 검토에서 6단계 이후의 예전 10×10 저장판이 새 최대 크기 검사에 걸릴 수 있음을 발견했다. 옛 6×6·10×10 판은 그대로 이어하고 다음 단계에서 새 크기로 확장하도록 허용한다. 별도 단위/브라우저 마이그레이션 검증을 추가한다.

- 리브 WebKit 재로딩 검증에서 시작 클릭 뒤 홈 캐러셀에 머문 기존 간헐 실패가 재발했다. trace는 노래 복원 이전 [data-resume] 대기에서 멈췄다. 화면 밖 시작 버튼을 바로 겨냥하던 테스트를 실제 사용자 순서(리브 탭 선택 → 보이는 시작 버튼)로 바꾸고 리브 전체 흐름을 재확인한다. 앱에서 곡 순서가 손실된 것으로 단정하지 않는다.

- 단위 테스트 173개 통과(`unit-final.log`), ESLint 및 Vite 빌드 통과. 단계 1·2·3·4·10·15에서 목표 영역을 선택하는 플레이가 실제 시간·교환 예산 안에 종료됨을 검증했다.
- 관련 브라우저 고유 시나리오 **216개** 확인. `browser-final.log`에서 변경 없는 105개 통과와, 최종 저장 호환성 수정 및 테스트 흐름 보정 뒤 `browser-verified.log`의 111개 통과를 합친 수다. PC Chromium / 모바일 Chromium / iPhone WebKit. 최초 실패 로그도 별도 보존한다.
