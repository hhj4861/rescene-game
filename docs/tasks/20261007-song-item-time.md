# 노래 아이템 시간 보장과 재등장 제한

- 목표: 노래 아이템 획득 시 남은 시간을 최소 60초로 올린다(사용자 선택: 20초 → 60초). 60초 이상 남았으면 유지한다. 획득 후 노래가 끝날 때까지 다른 노래 아이템을 노출하지 않는다.
- 범위/소유: Codex 단독, feat/arcade-game-rules-refresh / e0ae2b8 기준의 기존 구현 worktree. 원이·메이·제나·리브의 실제 노래 아이템 경로, 시간·대기 저장 및 안내. 펌프는 노래 아이템이 없으므로 기존 60초 박자표를 유지한다.
- 규칙: 음소거/오디오 실패에도 시간 보너스는 적용. 시계 보너스는 별도 유지. 목숨 소진·교환 횟수 소진·목표 달성 규칙은 그대로다. 재생 중 아이템 획득은 거부하고, 필드의 다른 노래 아이템을 정리하고, 제나가 이미 보유한 노래는 버리지 않고 버튼을 숨겨 대기시킨다. 원이 41초, 메이·제나 60초, 리브 20초 동안 재등장하지 않으며 리브의 기존 최소 24초 간격도 유지한다. 일시정지는 대기도 멈추고, 이어지는 실제 음원이 있으면 다음 스테이지에서도 대기를 유지한다.
- 완료 기준: 네 게임 모두 실제 아이템 획득·만료 경계·음소거·일시정지·저장 복원·중복 제한·재등장을 모델/브라우저에서 검증. 빌드 및 본인 변경 커밋·upstream push, 로컬 미리보기와 PR #28 갱신. 머지·운영 배포는 별도 승인 대상.
- 현재: 구현·검증 완료. 본인 변경 커밋·upstream push 및 PR 설명 갱신 단계. 증적은 iCloud 작업 루트 rescene-game/song-item-time-20261007 아래 저장한다.

- 1차 단위 검증에서 제나 보유 노래가 사라지는 회귀를 발견해 보유 수는 유지하고 재생 중 버튼만 숨기도록 수정했다. 리브의 기존 노래 타이머를 공통 등장 제한 시간에도 동일하게 사용하도록 맞췄다.

- 브라우저 검증 보정: 제나는 버튼 획득 시 정확히 60초에서 시작하며 화면은 올림 표시를 사용한다. 1,000ms 가상 시간의 마지막 렌더가 다음 프레임 직전일 수 있어 59초 표시 검증을 1,100ms로 바꿨다. 리브 브라우저 시간 검증은 기존 모의 YouTube API를 사용해 외부 네트워크에 의존하지 않게 했다.

- 리브 시간 테스트가 멈춘 원인은 일시정지 오버레이가 음소거 버튼을 가린 상태에서 테스트가 먼저 클릭한 것이었다. 가상 시간을 멈춘 채 ‘계속하기 → 음소거 → 획득’ 순으로 실제 사용자 조작을 수행하도록 수정했다.

- 기존 리브 WebKit 이어하기 테스트에서 새로고침 후 시작 클릭이 홈 화면에 머무른 1회 실패를 trace로 확인했다(노래/시간 상태 검증 전). 같은 코드·빌드로 리브 파일을 별도 재검증하며, 최종 결과와 최초 실패 로그를 모두 보존한다.
